# 은퇴 커리어 공유 카드 설계

작성일: 2026-11-26 · 대상 버전: 1.3.0 (새 기능, MINOR)

## 의도와 이유

은퇴한 선수의 커리어를 **한 장의 카드 이미지**로 보기 좋게 정리하고, 플레이어가 그 이미지를 저장하거나 인스타그램·카카오톡 등으로 공유할 수 있게 한다. 목적은 **게임 홍보**: 친구가 카드를 보고 카드에 적힌 게임 주소로 들어오게 하는 것.

## 목표

- 은퇴한 커리어 하나를 한 장(세로형) 카드로 보여 준다.
- 카드 바로 밑에 버튼 두 개: **이미지 저장하기**, **공유하기**.
- 카드 이미지 맨 아래에 **게임 주소만** 적는다.
- 팀 로고는 **공식 로고**를 그대로 쓴다 (사용자 결정).
- 미리보기로 보이는 카드와 저장·공유되는 이미지가 같아야 한다.

## 하지 않을 것 (이번 범위 밖)

- 진행 중(은퇴 전) 커리어의 카드. 은퇴한 커리어만 (사용자 결정).
- 받은 사람이 누를 수 있는 커리어 링크, 링크 미리보기, 서버 저장 (B안, 나중 검토).
- 카카오 SDK 공유 말풍선, 인스타 전용 연동. 휴대폰 기본 공유 창만 쓴다.
- "나도 MVP 도전하기" 같은 홍보 문구. **넣지 않는다** (사용자 결정).

## 실패로 보는 경우 (기술적으로 동작해도)

- 저장된 이미지에 로고가 빠지거나 빈 칸·대체 엠블럼으로 나오는데 사용자에게 알리지 않는 것.
- 아이폰 사파리에서 첫 저장 때 글꼴이 기본 글꼴로 바뀌거나 이미지가 비는 것.
- 카드 글씨가 휴대폰 화면이나 인스타 스토리에서 읽기 어려울 만큼 작은 것.

## 제약

- 세이브는 브라우저 localStorage에만 있다. 카드는 클라이언트에서만 만든다. 서버 저장 없음.
- 데이터 원천: `CareerRetrospective` (`src/types/game.ts`). 새 은퇴는 `buildCareerRetrospective`로, 예전 명예의 전당 항목은 `buildFallbackRetrospectiveFromHof`(`src/engine/retrospectiveEngine.ts`)로 얻는다. 세이브 구조는 바꾸지 않는다.
- 로고 출처:
  - 약 133팀은 같은 서버의 `public/logos/*` 파일이다. 그대로 캡처할 수 있다.
  - NBA·NCAA·G리그 등 ESPN 로고(`https://a.espncdn.com/...`)는 다른 사이트 이미지다. 그대로 쓰면 캔버스가 오염되어 저장이 막힐 수 있다. 런타임 로고 맵은 `useCareerStore`의 `espnLogos`에 있고(`Header.tsx`에서 채움), `TeamEmblem`이 그 맵을 읽는다.
- 글꼴: Pretendard를 jsdelivr CDN 스타일시트로 불러온다 (`app/layout.tsx`).
- 버전·패치노트 절차: `GAME_VERSION`(`src/config/appMeta.ts`)과 `package.json`의 `version`을 함께 1.3.0으로 올리고, `src/data/patchNotes.ts` 맨 앞에 요약형 노트를 추가한다.

## 검토한 방법 (Approaches)

1. **화면의 카드를 그대로 캡처 — 선택됨.** 카드를 일반 React 컴포넌트(Tailwind)로 그리고, `html-to-image`로 PNG로 바꾼다. 장점: 미리보기와 결과가 같고, 기존 디자인 토큰을 재사용하며, 서버 비용이 없다. 단점: 의존성 하나가 추가되고, iOS 사파리 첫 캡처 문제에 대비해야 한다.
2. 캔버스에 직접 그리기. 가장 안정적이지만 디자인을 바꿀 때마다 그리는 코드를 다시 짜야 한다.
3. 서버(`ImageResponse`)에서 PNG 생성. 기기 차이가 없고 B안의 기반이 되지만, 서버 비용이 들고 한글 글꼴을 번들해야 하며 CSS 표현에 제약이 있다.

사용자가 1번을 골랐다. 지금은 서버가 필요 없는 A안이고, 보이는 것과 저장되는 것이 같다는 점을 가장 중요하게 봤다.

## 사용자가 정한 것

- A안: 이미지 + 게임 주소. 링크 공유는 하지 않는다.
- 카드 하단에는 게임 주소만 넣는다. 홍보 문구는 넣지 않는다.
- 버튼은 두 개: 이미지 저장하기, 공유하기.
- 은퇴한 커리어만 대상으로 한다.
- 팀 로고는 공식 로고를 쓴다. **안 되면 사용자에게 보고한다** (대체 엠블럼으로 조용히 바꾸지 않는다).
- 만드는 방법은 1번(화면 캡처)이다.

## 설계

### 진입점

- 은퇴식/명예의 전당 다시 보기 화면(`RetirementCeremony.tsx`, 실시간 은퇴와 `replayEntry` 다시 보기 모두)에 **"커리어 카드"** 버튼을 둔다. 누르면 기존 `Modal`(`src/components/common/Modal.tsx`)로 카드 미리보기와 버튼 두 개를 띄운다. (제안: 정확한 버튼 위치는 builder 판단)

### 카드 구성 (기록 범위·주소는 사용자 결정, 배치는 제안)

세로형 1080×1350(4:5) 출력을 기준으로 한다. 인스타 피드와 카톡 미리보기에서 잘리지 않는 비율이다.

```
┌──────────────────────────┐
│  [레거시 등급 이모지·제목 · 점수]   │
│  이름  #등번호  포지션 · 키        │
│  시작–은퇴 연도 · N시즌 · 은퇴 나이  │
│ ──────────────────────── │
│  통산 PPG / RPG / APG (+ 최고 OVR) │
│  우승 · MVP · 파이널 MVP · 올스타   │
│  팀 이력: [로고] → [로고] → [로고]   │
│  커리어 하이 득점 · 피크 시즌        │
│ ──────────────────────── │
│           게임 주소              │
└──────────────────────────┘
   [ 이미지 저장하기 ]  [ 공유하기 ]
```

- 기록 범위 (사용자 결정): 통산 기록과 우승·MVP·파이널 MVP·올스타는 **전체 커리어 합계**(`totals`, `averages`)를 크게 보여 준다. NBA에서 뛴 커리어(`totals.nbaGp > 0`)면 그 밑에 **NBA 따로** 한 줄을 더 보여 준다 (`nbaPoints`, `nbaChampionships`, `nbaMvps` 등 있는 값만).
- 맨 아래 게임 주소: `roadtomvp.vercel.app` (사용자 제공 `https://roadtomvp.vercel.app/`). 상수 하나로 둔다.
- 팀 이력은 `stints`를 쓰고, 팀이 많으면 앞뒤 대표 팀만 보이고 나머지는 "+N"으로 줄인다.
- 0인 수상 항목은 숨긴다.
- 카드 색은 테마(라이트/다크)와 관계없이 **고정된 카드 전용 배색**을 쓴다. 공유 이미지가 보는 사람의 설정과 상관없이 같아야 하기 때문이다.

### 이미지 만들기

- `html-to-image`의 `toBlob`(또는 `toPng`)으로 카드 DOM을 캡처한다. `pixelRatio`는 출력 폭이 1080px이 되게 맞춘다.
- iOS 대비: 캡처 전에 `document.fonts.ready`와 카드 안 모든 `<img>`의 `decode()`를 기다린다. 알려진 첫 캡처 누락 문제 때문에 실제 결과를 쓰기 전 한 번 미리 캡처(warm-up)한다.
- 글꼴: Pretendard 웹폰트가 캡처 결과에 포함되는지 확인한다. 빠지면 `html-to-image`의 `fontEmbedCSS` 옵션으로 직접 넣는다.

### 공식 로고 처리

- 카드 안 로고는 **같은 서버를 거친 주소**로 바꿔 쓴다. 외부 로고 URL은 Next 이미지 변환 주소(`/_next/image?url=<인코딩한 원본>&w=256&q=90`)로 감싸고, `next.config.ts`의 `images.remotePatterns`에 `a.espncdn.com`을 추가한다. 같은 서버의 `/logos/*`는 그대로 쓴다.
- 로고 주소는 `TeamEmblem`과 같은 순서(`espnLogos` 맵 → `team.logoUrl`)로 정한다. 카드용 작은 헬퍼로 분리하고, 기존 `TeamEmblem` 동작은 바꾸지 않는다.
- 로고 하나라도 실패하면 대체 엠블럼으로 조용히 바꾸지 않는다. 화면에 "일부 팀 로고를 불러오지 못했어요" 같은 안내와 **다시 시도** 버튼을 띄우고, 로고가 모두 나올 때까지 **저장·공유 버튼을 잠근다** (사용자 결정). 로고 빠진 카드가 퍼지지 않게 하기 위해서다.
- 비용 메모 (내 판단): 운영은 Vercel(`roadtomvp.vercel.app`)이다. `/_next/image` 변환은 원본 이미지 수 기준으로 사용량이 잡힌다. ESPN 로고 원본은 약 115개이고 변환 결과는 캐시되므로 부담은 작다고 본다.
- 예전 명예의 전당 항목(fallback 회고)은 팀 이력이 대표 팀 하나뿐이다. 그 경우 팀 이력 줄에는 그 팀만 보여 준다 (내 판단).
- 배포 후 실제 미리보기 배포에서 ESPN 로고가 들어간 카드를 저장해 보고, 결과를 사용자에게 보고한다.

### 버튼 동작

- **이미지 저장하기**: PNG Blob을 `<a download>`로 내려받는다. 파일 이름 예: `road-to-mvp-<선수이름>.png`. iOS 사파리에서 다운로드가 안 되면 이미지를 새 창으로 열고 "길게 눌러 저장" 안내를 띄운다.
- **공유하기**: `navigator.canShare({ files })`가 참이면 `navigator.share({ files: [png] })`로 휴대폰 기본 공유 창을 연다. 거기서 인스타 스토리, 카톡 등을 고른다. 지원하지 않는 브라우저(대부분 PC)에서는 "이 브라우저는 바로 공유를 지원하지 않아요. 이미지 저장하기 후 올려 주세요" 안내를 띄운다. 사용자가 공유 창을 닫은 경우(`AbortError`)는 오류로 보지 않는다.
- 캡처하는 동안 두 버튼을 잠그고 진행 표시를 한다.

### 공유 횟수 통계 (사용자 허락: 이번 작업에 한해)

- 새 분석 이벤트 `career_card_shared`를 추가한다. CLAUDE.md의 새 이벤트 절차를 따른다.
  1. `src/lib/analyticsSchema.ts`: `ANALYTICS_EVENT_NAMES`, 페이로드 타입, 검증 로직, 속도 제한 규칙(예: 10분에 20회)을 추가한다.
  2. 새 마이그레이션 `supabase/migrations/20261128_analytics_career_card_event.sql`을 만든다. `analytics_events_event_name_check` 제약에 새 이벤트를 더한다. 기존 파일 중 가장 늦은 날짜가 `20261127`이라 버전 번호가 겹치지 않게 `20261128`을 쓴다. 기존 파일 이름은 바꾸지 않는다.
  3. README 마이그레이션 목록에 추가한다. 배포 **전에** 사용자에게 CLAUDE.md 형식(제목 · 전체 SQL · 실행 방법)으로 실행을 요청한다.
- 페이로드 (내 판단, 개인정보 없음):
  - `action`: `'save' | 'share'`
  - `legacyTierId`, `seasonsPlayed`, `reachedNba`
  - `isReplay`: 명예의 전당 다시 보기에서 만들었는지
- 실제로 성공했을 때만 보낸다. 저장은 다운로드를 시작한 시점, 공유는 `navigator.share`가 성공한 시점이다. 공유 창을 닫은 경우(`AbortError`), 로고 실패로 잠긴 경우, PC 미지원 안내만 뜬 경우는 보내지 않는다.
- 보내는 방법은 기존 클라이언트 분석 전송 경로를 그대로 쓴다.

### 테스트

- 카드에 들어갈 값을 만드는 순수 함수(`CareerRetrospective` → 카드 표시 데이터: 숨길 수상, 팀 이력 줄이기, 로고 주소 변환)는 `src/engine/` 또는 `src/lib/` 아래에 두고 `bun test` 테스트를 쓴다.
- 캡처·공유는 Playwright로 미리보기 화면에서 수동 확인한다 (데스크톱 + 모바일 에뮬레이션).
- PR 전에 `bun run typecheck && bun run lint && bun run test && bun run balance:check`.

### 버전·패치노트

- 1.3.0. 패치노트에 새 기능을 체감형 3~5줄로 적는다. 세이브 영향은 없다.

## Builder에게 맡기는 것

- 컴포넌트 파일 이름과 위치 (`src/components/retirement/` 아래 권장).
- 카드의 세부 타이포그래피와 간격. 기존 디자인 토큰을 따른다.
- warm-up 캡처 횟수와 기다리는 방식의 세부.
